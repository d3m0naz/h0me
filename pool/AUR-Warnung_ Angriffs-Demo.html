🛡️ Warnung: Das AUR ist ungeprüft

Das AUR ist kein offizielles Repository. Jeder kann Pakete hochladen, niemand prüft sie vorher. Ein AUR-Paket ist kein fertiges Programm, sondern ein Baurezept (PKGBUILD) – ein Shell-Skript, das beim Installieren mit deinen Rechten ausgeführt wird. Wer das Rezept nicht liest, führt blind fremden Code aus.

Warum gerade pamac gefährlich sein kann

Grafische Helfer wie pamac (Manjaro) oder yay machen AUR-Installs bequem – ein Klick, fertig. Genau das ist das Problem: Der entscheidende Schritt, das PKGBUILD lesen, wird übersprungen oder weggeklickt. In pamac muss AUR-Unterstützung bewusst aktiviert werden, und die Vorschau des Build-Skripts wird oft ignoriert.

Was im Hintergrund passiert ist (die 5 Schritte oben)

1
Tarnung: Das Paket heißt fast wie ein echtes – z. B. firefox-patch-bin statt firefox-bin. „fix“ oder „patched“ im Namen wirken seriös.
2
Ein Zeile reicht: Im PKGBUILD lädt eine Funktion ein Skript von einem fremden Server (curl … | bash) und führt es sofort aus.
3
Ausführung beim Bauen: Der Code läuft schon während makepkg – nicht erst beim Starten des Programms. Oft mit sudo-Rechten für die Installation.
4
Persistenz: Die Malware nistet sich als systemd-Dienst ein (im echten Fall getarnt als systemd-initd) und startet nach jedem Reboot neu.
5
Kontrollverlust: Ein RAT (Remote Access Trojan) öffnet eine Verbindung nach außen. Der Angreifer kann Dateien lesen, löschen, verschlüsseln oder weitere Schadsoftware nachladen.

Das ist real passiert – keine Theorie

JULI 2025
Chaos RAT im AUR
Pakete wie firefox-patch-bin, librewolf-fix-bin und zen-browser-patched-bin luden den Chaos RAT von GitHub nach. Sie blieben rund 48 Stunden online, bevor das Arch-Team sie entfernte.
JULI 2018
acroread-Übernahme
Ein verwaistes Paket (acroread) wurde von einem Fremden adoptiert und um eine curl|bash-Zeile ergänzt, die Systemdaten abgriff und einen Dienst alle 360 Sekunden neu startete.

Das AUR selbst weist auf der Startseite ausdrücklich darauf hin: Nutzung auf eigenes Risiko. Grafische AUR-Helfer gelten als noch riskanter als das manuelle Bauen.

So schützt du dich

✓ Immer das PKGBUILD lesen, bevor du baust. Misstrauisch werden bei curl, wget, | bash oder unbekannten URLs.

✓ .install-Dateien prüfen – dort versteckt sich oft Code, der mit Root-Rechten läuft.

✓ Alter & Stimmen checken: Wie lange gibt es das Paket? Viele Votes? Ein brandneues „Fix“-Paket ohne Historie ist ein Warnsignal.

✓ Tippfehler-Namen meiden: Nimm das offizielle Paket, nicht die „patched“-Variante daneben.

✓ Wenn möglich: offizielle Repos statt AUR – und AUR-Helfer nur einsetzen, wenn du weißt, was du tust.
