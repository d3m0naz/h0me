00Platzhalter

Alle Werte in dieser Anleitung sind Beispiele aus den reservierten Dokumentationsbereichen. Ersetze sie vor dem Kopieren durch deine eigenen.

PlatzhalterBedeutung
hs.example.comÖffentlicher Name des headscale-Servers
ts.example.comMagicDNS-Domain für Geräte im Tailnet. Muss sich von der Server-Domain unterscheiden.
203.0.113.10Öffentliche IPv4 des VPS
2001:db8::10Öffentliche IPv6 des VPS
adminDein Admin-Benutzer auf dem Server
alice, bobheadscale-User, meist ein User pro Gerät oder Person
100.64.0.XTailnet-IP eines Geräts, aus headscale nodes list

Voraussetzung: ein VPS mit frischem Debian 13 (trixie), Root-Zugang per SSH und eine Domain, deren DNS du verwalten kannst.

01DNS-Einträge Pflicht

Lege beim DNS-Anbieter zwei Einträge an. Caddy holt das TLS-Zertifikat erst, wenn der Name auf den Server zeigt.

NameTypWert
hs.example.comA203.0.113.10
hs.example.comAAAA2001:db8::10

Für ts.example.com brauchst du keinen Eintrag. MagicDNS löst diese Namen nur innerhalb des Tailnets auf.

dig +short hs.example.com A
dig +short hs.example.com AAAA

02Admin-User & SSH Pflicht

Als root anmelden, Hostname setzen und einen eigenen Admin-User mit sudo anlegen.

apt update && apt full-upgrade -y
hostnamectl set-hostname hs
sed -i 's/^127\.0\.1\.1.*/127.0.1.1 hs.example.com hs/' /etc/hosts

adduser admin
usermod -aG sudo admin
echo 'admin ALL=(ALL:ALL) ALL' > /etc/sudoers.d/90-admin
chmod 440 /etc/sudoers.d/90-admin
visudo -c

Vom eigenen Rechner aus den SSH-Key hinterlegen und den Login testen:

ssh-copy-id admin@hs.example.com
ssh admin@hs.example.com

SSH absichern

/etc/ssh/sshd_config.d/10-hardening.conf
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
/etc/ssh/sshd_config.d/20-extra.conf
AllowUsers admin
MaxAuthTries 3
X11Forwarding no
AllowAgentForwarding no
sudo sshd -t && sudo systemctl reload ssh
Aussperren vermeiden

Lass die aktuelle Sitzung offen und teste den Key-Login in einem zweiten Terminal, bevor du sie schließt. Ab hier läuft alles als admin mit sudo.

03Automatische Updates Pflicht

sudo apt install -y unattended-upgrades
/etc/apt/apt.conf.d/20auto-upgrades
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";
/etc/apt/apt.conf.d/52unattended-reboot
Unattended-Upgrade::Automatic-Reboot "true";
Unattended-Upgrade::Automatic-Reboot-Time "04:00";
sudo unattended-upgrade --dry-run --debug 2>&1 | tail -n 20

unattended-upgrades aktualisiert nur Pakete aus den Debian-Quellen. headscale (eigenes .deb) und Tailscale (eigenes Repo) musst du selbst aktualisieren.

04Firewall & fail2ban Pflicht

Eingehend ist alles gesperrt, außer SSH mit Rate-Limit und HTTP/HTTPS für Caddy.

sudo apt install -y ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw limit 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status verbose

fail2ban

sudo apt install -y fail2ban python3-systemd
/etc/fail2ban/jail.local
[DEFAULT]
backend   = systemd
banaction = ufw

[sshd]
enabled = true
sudo systemctl restart fail2ban
sudo fail2ban-client status sshd

05Kernel & Dienste Empfohlen

/etc/sysctl.d/99-hardening.conf
# Loose statt strict, damit ein späterer Exit-Node funktioniert
net.ipv4.conf.all.rp_filter = 2
net.ipv4.conf.default.rp_filter = 2
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.default.accept_redirects = 0
net.ipv6.conf.all.accept_redirects = 0
net.ipv6.conf.default.accept_redirects = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.all.accept_source_route = 0
net.ipv6.conf.all.accept_source_route = 0
net.ipv4.tcp_syncookies = 1
net.ipv4.icmp_echo_ignore_broadcasts = 1
kernel.kptr_restrict = 2
kernel.dmesg_restrict = 1
sudo sysctl --system >/dev/null

LLMNR und mDNS abschalten

Nur nötig, wenn systemd-resolved läuft (systemctl is-active systemd-resolved).

/etc/systemd/resolved.conf.d/no-llmnr.conf
[Resolve]
LLMNR=no
MulticastDNS=no
sudo systemctl restart systemd-resolved

Unnötige Pakete entfernen

Viele VPS-Images bringen einen Mailserver mit. Wenn der Server keine Mails verschicken soll:

sudo apt purge -y 'exim4*' logwatch && sudo apt autoremove -y

06headscale installieren Pflicht

headscale hat kein apt-Repo. Das offizielle .deb aus den GitHub-Releases enthält Binary, systemd-Unit und Beispielkonfiguration. Lies vor jedem Update die Release-Notes, weil sich Config-Optionen und CLI-Flags zwischen Versionen ändern.

VER=$(curl -s https://api.github.com/repos/juanfont/headscale/releases/latest | grep -oP '"tag_name": "v\K[^"]+')
ARCH=$(dpkg --print-architecture)
curl -fLo /tmp/headscale.deb "https://github.com/juanfont/headscale/releases/download/v${VER}/headscale_${VER}_linux_${ARCH}.deb"
sudo apt install -y /tmp/headscale.deb && rm /tmp/headscale.deb
headscale version

Für ein späteres Update führst du denselben Block noch einmal aus und startest danach mit sudo systemctl restart headscale neu.

07headscale konfigurieren Pflicht

sudo cp /etc/headscale/config.yaml /etc/headscale/config.yaml.orig
sudoedit /etc/headscale/config.yaml

Diese drei Werte anpassen, alles andere bleibt auf dem Standard:

/etc/headscale/config.yaml (Auszug)
server_url: https://hs.example.com
listen_addr: 127.0.0.1:8080   # nur lokal, Caddy macht TLS
dns:
  base_domain: ts.example.com
sudo systemctl enable --now headscale
sudo systemctl status headscale --no-pager

08Caddy & TLS Pflicht

Caddy ist in Debian enthalten, holt das Let's-Encrypt-Zertifikat selbst und leitet auf den lokalen headscale-Port weiter.

sudo apt install -y caddy
/etc/caddy/Caddyfile
hs.example.com {
    reverse_proxy 127.0.0.1:8080
}
sudo systemctl reload caddy
curl -s https://hs.example.com/health

Erwartete Antwort: {"status":"pass"}. Wenn das Zertifikat fehlt, prüfe DNS und ob Port 80 offen ist.

09User & Keys Pflicht

sudo headscale users create alice
sudo headscale users list
sudo headscale preauthkeys create --user alice --expiration 24h
sudo headscale nodes list

Je nach Version erwartet --user den Namen oder die numerische ID aus users list. Die Meldung „user not found“ heißt meist, dass der User noch nicht angelegt ist.

Ein User pro Gerät

ACLs arbeiten mit Usern. Wenn du Geräte später unterschiedlich berechtigen willst, gib jedem einen eigenen User.

10Clients verbinden Pflicht

Linux und macOS (CLI) mit Pre-Auth-Key

sudo tailscale up --login-server https://hs.example.com --authkey <KEY>
  • macOS-App per CLI: /Applications/Tailscale.app/Contents/MacOS/Tailscale up …
  • Homebrew: erst sudo brew services start tailscale, dann tailscale up …

macOS-App (GUI)

Mit gedrückter ⌥-Taste aufs Menüleisten-Icon klicken, dann Debug → Custom Login Server und https://hs.example.com eintragen.

iPhone und iPad

In der Tailscale-App auf Log in tippen, dann ⋯ → Use custom coordination server und https://hs.example.com eintragen. In älteren Versionen steht die Option unter iOS-Einstellungen → Tailscale → Alternate Coordination Server URL.

Die Login-Seite zeigt einen Registrierungs-Key. Diesen auf dem Server bestätigen:

sudo headscale nodes register --user alice --key <KEY>

11ACLs Optional

Ohne Policy darf jedes Gerät jedes andere erreichen. Das Beispiel setzt drei typische Rollen um:

UserRolleDarf erreichen
alice@, bob@, nas@vertrautalles
kiosk@eingeschränktnichts von sich aus, ist aber erreichbar
gast@Gastnur 8096/tcp auf dem Medienserver
/etc/headscale/acl.hujson
{
  "groups": {
    // alle Geräte außer kiosk und gast
    "group:trusted": ["alice@", "bob@", "nas@"]
  },
  "hosts": {
    // Tailnet-IP des Medienservers
    "media": "100.64.0.X/32"
  },
  "acls": [
    { "action": "accept", "src": ["group:trusted"], "dst": ["*:*"] },
    // gast: nur Medienserver, nur 8096/tcp
    { "action": "accept", "src": ["gast@"], "proto": "tcp", "dst": ["media:8096"] }
    // kiosk@: keine Regel, darf nichts initiieren
  ]
}
  • ACLs sind stateful. Antworten auf erlaubte Verbindungen kommen immer zurück, deshalb braucht kiosk@ keine eigene Regel.
  • Den Medienserver über hosts per IP freigeben, nicht per User. Sonst wären alle Geräte dieses Users auf Port 8096 erreichbar.
  • Der Gast braucht einen eigenen User und gehört nicht in group:trusted.
  • Die Schreibweise mit @ am Ende gilt ab headscale 0.26.

Policy in der Config aktivieren:

/etc/headscale/config.yaml (Auszug)
policy:
  mode: file
  path: /etc/headscale/acl.hujson
sudo systemctl restart headscale
journalctl -u headscale -n 20 --no-pager

Testen

tailscale ping ignoriert ACLs. Teste mit normalem ping und curl:

# auf einem vertrauten Gerät: klappt
ping -c2 100.64.0.1
# auf kiosk: blockiert
ping -c2 -W2 100.64.0.2
# auf gast: Antwort vom Medienserver
curl -sI http://100.64.0.X:8096 | head -1
# auf gast: blockiert
ping -c2 -W2 100.64.0.X

Der Gast ruft den Medienserver per IP auf. Der hosts-Eintrag gilt nur für IPv4. Über den MagicDNS-Namen probiert der Client eventuell zuerst IPv6 und hängt.

Vorsicht

Neue Geräte haben keinen Zugriff, bis ihr User in group:trusted steht. Eine fehlerhafte Policy kann das ganze Tailnet sperren. SSH über die öffentliche IP bleibt der Rettungsweg.

Soll ein eingeschränktes Gerät den Exit-Node nutzen, ergänze: { "action": "accept", "src": ["kiosk@"], "dst": ["autogroup:internet:*"] }

12Exit-Node Optional

Der Server leitet den gesamten Internet-Verkehr eines Clients weiter, zum Beispiel im fremden WLAN. Dafür läuft auf dem Server zusätzlich ein Tailscale-Client, der sich am eigenen headscale anmeldet.

Tailscale-Client aus dem offiziellen Repo
curl -fsSL https://pkgs.tailscale.com/stable/debian/trixie.noarmor.gpg | sudo tee /usr/share/keyrings/tailscale-archive-keyring.gpg >/dev/null
curl -fsSL https://pkgs.tailscale.com/stable/debian/trixie.tailscale-keyring.list | sudo tee /etc/apt/sources.list.d/tailscale.list >/dev/null
sudo apt update && sudo apt install -y tailscale
IP-Forwarding
sudo tee /etc/sysctl.d/99-tailscale.conf >/dev/null <<'EOF'
net.ipv4.ip_forward = 1
net.ipv6.conf.all.forwarding = 1
EOF
sudo sysctl --system >/dev/null
Firewall
WAN=$(ip route show default | awk '{print $5; exit}')
sudo ufw allow 41641/udp
sudo ufw route allow in on tailscale0 out on "$WAN"
Verbinden und Exit-Node anbieten
sudo headscale preauthkeys create --user admin --expiration 1h
sudo tailscale up --login-server https://hs.example.com --authkey <KEY> \
  --advertise-exit-node --accept-dns=false
In headscale freigeben
sudo headscale nodes list
sudo headscale nodes approve-routes --identifier <ID> --routes 0.0.0.0/0,::/0
sudo headscale nodes list-routes

Für den Server-Client legst du vorher mit headscale users create admin einen User an. Nutzt du ACLs, muss dieser User in group:trusted stehen.

Nutzen

  • iPhone: Exit Node → hs
  • macOS-App: Exit Nodes → hs
  • CLI: tailscale set --exit-node=hs

Test: ifconfig.me zeigt jetzt die IP des Servers.

Updates

Tailscale kommt aus einem Fremd-Repo und wird von unattended-upgrades nicht erfasst. Entweder regelmäßig apt upgrade ausführen oder den Origin aus apt-cache policy tailscale in Unattended-Upgrade::Origins-Pattern aufnehmen.

13Backup

Diese Pfade reichen, um den Server neu aufzusetzen, ohne dass sich Clients neu anmelden müssen:

PfadInhalt
/var/lib/headscale/Datenbank, Noise- und DERP-Keys
/etc/headscale/config.yamlKonfiguration
/etc/headscale/acl.hujsonPolicy, falls genutzt
/etc/caddy/CaddyfileReverse-Proxy
 
sudo systemctl stop headscale
sudo tar czf ~/headscale-backup-$(date +%F).tar.gz \
  /var/lib/headscale /etc/headscale /etc/caddy/Caddyfile
sudo systemctl start headscale

Das Archiv enthält private Schlüssel. Lade es nur verschlüsselt auf einen anderen Rechner.

14Fehlersuche

journalctl -u headscale -n 50 --no-pager
journalctl -u caddy -n 50 --no-pager
sudo fail2ban-client status sshd
sudo ufw status verbose
curl -s https://hs.example.com/health

Abschluss-Check

  • SSH-Login nur mit Key als admin, root-Login abgelehnt
  • ufw status zeigt nur 22, 80, 443 (plus 41641/udp mit Exit-Node)
  • /health antwortet mit pass über gültiges TLS
  • Mindestens zwei Clients sehen sich in tailscale status
  • MagicDNS-Namen unter ts.example.com lösen auf
  • Backup liegt außerhalb des Servers
Alle Namen, Domains und Adressen sind Beispiele (example.com, 203.0.113.0/24, 2001:db8::/32).
