1. Überblick

Ein Shell-Skript liest jede Minute die Drehzahl des Gehäuselüfters über den Linux-hwmon-Sensor aus. Liegt die Drehzahl drei Messungen in Folge unter dem Grenzwert, wird einmalig eine Warnung ins Systemlog geschrieben und per Mail verschickt. Sobald der Lüfter wieder läuft, folgt eine Entwarnung. Weitere Mails gibt es währenddessen nicht.

2. System

KomponenteWert
MainboardASRock J5005-ITX (Intel Pentium Silver J5005)
Betriebssystemopenmediavault 8.x (Debian 13), Kernel 7.3.4+deb13-amd64
Sensor-ChipNuvoton, hwmon-Name nct6796 (z. B. /sys/class/hwmon/hwmon3)
Kernelmodulnct6775 (deckt alle Nuvoton-NCT67xx-Chips ab)

3. Sensortreiber

Installation und Laden

apt install lm-sensors
sensors-detect --auto
modprobe nct6775
echo nct6775 > /etc/modules-load.d/nct6775.conf   # beim Booten automatisch laden
sensors
Modulname ≠ Chipname: Das Kernelmodul heißt immer nct6775. Unter /sys/class/hwmon/hwmon*/name steht dagegen der tatsächliche Chip, hier nct6796. Ein Modul nct6796 gibt es nicht. modprobe nct6796 schlägt daher fehl, und lsmod | grep nct6796 findet nichts. Richtig ist lsmod | grep nct.

Chip und Lüfter ermitteln

grep . /sys/class/hwmon/hwmon*/name
# acpitz, acpi_fan, coretemp, nct6796

grep . /sys/class/hwmon/hwmon*/fan*_input
watch -n1 sensors      # Gehäuselüfter kurz anhalten: der Wert, der auf 0 fällt, ist der richtige

Nicht belegte Lüfteranschlüsse zeigen dauerhaft 0 RPM und werden ignoriert.

Falls der Chip nicht erkannt wird

Zeigt dmesg | grep -i nct einen „resource conflict“, reserviert das BIOS die Sensoradressen per ACPI. Abhilfe in /etc/default/grub:

GRUB_CMDLINE_LINUX_DEFAULT="quiet acpi_enforce_resources=lax"
update-grub && reboot

4. Überwachungsskript

Pfad: /usr/local/sbin/fan-monitor.sh (Rechte 755, Besitzer root)

Konfiguration

VariableWertBedeutung
CHIPnct6796hwmon-Name des Sensor-Chips. Das Skript sucht das passende hwmonX-Verzeichnis selbst, weil sich die Nummer nach einem Neustart ändern kann.
FANfan1 / fan2 …Anschluss des Gehäuselüfters (siehe Abschnitt 3)
MIN_RPM300Unterhalb dieses Werts gilt der Lüfter als ausgefallen. Empfehlung: etwa ein Drittel der normalen Drehzahl.
FAIL_COUNT3So viele Fehlmessungen in Folge lösen den Alarm aus (verhindert Fehlalarme)
STATE_DIR/var/lib/fan-monitorZähler- und Alarmdateien
MAIL_TOleerLeer bedeutet: Empfänger aus der OMV-Benachrichtigung, ersatzweise root

Aktuelle Werte anzeigen:

grep -E '^(CHIP|FAN|MIN_RPM|FAIL_COUNT)=' /usr/local/sbin/fan-monitor.sh

Ablauf

  1. Sensorverzeichnis anhand von CHIP suchen und FAN_input lesen. Ist der Sensor nicht lesbar, gilt der Wert als −1 und wird wie ein Ausfall behandelt.
  2. Drehzahl unter MIN_RPM: Zähler erhöhen. Erreicht er FAIL_COUNT und besteht noch kein Alarm, werden Logeintrag und Mail mit der kompletten sensors-Ausgabe erzeugt und die Alarmdatei angelegt.
  3. Drehzahl in Ordnung: Zähler auf 0 setzen. Bestand ein Alarm, werden Entwarnung ins Log und per Mail geschickt und die Alarmdatei gelöscht.

Quelltext

#!/bin/bash
# fan-monitor.sh – Überwacht einen Gehäuselüfter (lm-sensors / hwmon)
# und meldet Ausfall/Wiederherstellung per Mail (OMV-Benachrichtigung) und syslog.
#
# Installation: /usr/local/sbin/fan-monitor.sh  (chmod 755)
# Aufruf alle 60 s per systemd-Timer.

# ===== Konfiguration =====================================================
CHIP="nct6796"     # hwmon-Name des Chips (ASRock J5005-ITX: nct6796)
FAN="fan2"            # welcher Lüfter, siehe: sensors (fan1, fan2, ...)
MIN_RPM=300           # darunter gilt der Lüfter als ausgefallen
FAIL_COUNT=3          # so viele Messungen in Folge unter MIN_RPM => Alarm
STATE_DIR="/var/lib/fan-monitor"
MAIL_TO=""            # leer = Empfänger aus OMV-Benachrichtigung, sonst "root"
# =========================================================================

HOST=$(hostname -f 2>/dev/null || hostname)
mkdir -p "$STATE_DIR"
CNT_FILE="$STATE_DIR/${FAN}.count"
ALARM_FILE="$STATE_DIR/${FAN}.alarm"

log() { logger -t fan-monitor "$*"; }

send_mail() {
    local subject="$1" body="$2" to="$MAIL_TO"
    if [ -z "$to" ] && command -v omv-confdbadm >/dev/null && command -v jq >/dev/null; then
        to=$(omv-confdbadm read conf.system.notification.email 2>/dev/null | jq -r '.primaryemail // empty')
    fi
    [ -z "$to" ] && to="root"
    printf 'To: %s\nSubject: [%s] %s\nContent-Type: text/plain; charset=UTF-8\n\n%s\n' \
        "$to" "$HOST" "$subject" "$body" | /usr/sbin/sendmail -t
}

# hwmon-Verzeichnis des Chips suchen (Nummer hwmonX kann sich nach Reboot ändern)
HWMON=""
for d in /sys/class/hwmon/hwmon*; do
    if [ "$(cat "$d/name" 2>/dev/null)" = "$CHIP" ]; then HWMON="$d"; break; fi
done

if [ -z "$HWMON" ] || [ ! -r "$HWMON/${FAN}_input" ]; then
    RPM=-1   # Sensor nicht lesbar -> wie Ausfall behandeln
else
    RPM=$(cat "$HWMON/${FAN}_input" 2>/dev/null || echo -1)
fi

count=$(cat "$CNT_FILE" 2>/dev/null || echo 0)

if [ "$RPM" -lt "$MIN_RPM" ]; then
    count=$((count + 1))
    echo "$count" > "$CNT_FILE"
    if [ "$count" -ge "$FAIL_COUNT" ] && [ ! -f "$ALARM_FILE" ]; then
        if [ "$RPM" -lt 0 ]; then
            msg="Lüftersensor $CHIP/$FAN ist nicht lesbar (Treiber geladen?)."
        else
            msg="Gehäuselüfter $FAN dreht nur noch mit $RPM U/min (Minimum: $MIN_RPM) – seit $count Messungen."
        fi
        log "ALARM: $msg"
        send_mail "WARNUNG: Gehäuselüfter ausgefallen" "$msg

Zeitpunkt: $(date '+%d.%m.%Y %H:%M:%S')

$(sensors 2>/dev/null)"
        date > "$ALARM_FILE"
    fi
else
    echo 0 > "$CNT_FILE"
    if [ -f "$ALARM_FILE" ]; then
        msg="Gehäuselüfter $FAN läuft wieder mit $RPM U/min."
        log "OK: $msg"
        send_mail "OK: Gehäuselüfter läuft wieder" "$msg

Zeitpunkt: $(date '+%d.%m.%Y %H:%M:%S')"
        rm -f "$ALARM_FILE"
    fi
fi

5. Zeitsteuerung (systemd)

/etc/systemd/system/fan-monitor.service

[Unit]
Description=Gehäuselüfter prüfen
[Service]
Type=oneshot
ExecStart=/usr/local/sbin/fan-monitor.sh

/etc/systemd/system/fan-monitor.timer

[Unit]
Description=Gehäuselüfter jede Minute prüfen
[Timer]
OnBootSec=2min
OnUnitActiveSec=60s
[Install]
WantedBy=timers.target

Aktivieren

systemctl daemon-reload
systemctl enable --now fan-monitor.timer

Der Timer startet das Skript 2 Minuten nach dem Booten und danach jede Minute. Änderungen am Skript gelten ab dem nächsten Aufruf, ein Neustart des Timers ist nicht nötig.

6. Mail-Benachrichtigung

Der Versand läuft über den in OMV konfigurierten Mailversand (/usr/sbin/sendmail). Voraussetzung: System → Benachrichtigung → Einstellungen ist aktiviert und eine Hauptempfänger-Adresse ist eingetragen. Der Betreff beginnt mit dem Hostnamen in eckigen Klammern.

EreignisBetreff
AusfallWARNUNG: Gehäuselüfter ausgefallen
WiederherstellungOK: Gehäuselüfter läuft wieder

7. Funktion prüfen und testen

Laufenden Betrieb prüfen

systemctl list-timers fan-monitor.timer   # nächste/letzte Ausführung
systemctl status fan-monitor.service      # Ergebnis der letzten Prüfung
cat /var/lib/fan-monitor/*.count          # Fehlmessungen in Folge (normal: 0)
journalctl -t fan-monitor --since today   # nur Einträge von heute
Hinweis zum Journal: journalctl zeigt den gesamten Verlauf. Alte Einträge bleiben stehen, auch wenn das Problem behoben ist. Das Skript schreibt nur bei Alarm oder Entwarnung. Kommen keine neuen Einträge dazu, ist alles in Ordnung.

Alarm testweise auslösen

sed -i 's/^MIN_RPM=.*/MIN_RPM=99999/' /usr/local/sbin/fan-monitor.sh
# ca. 3 Minuten warten
journalctl -t fan-monitor -n 5            # ALARM-Eintrag + Mail prüfen

sed -i 's/^MIN_RPM=.*/MIN_RPM=300/' /usr/local/sbin/fan-monitor.sh
# innerhalb einer Minute: OK-Eintrag + Entwarnungs-Mail

Zustand zurücksetzen

rm -f /var/lib/fan-monitor/*

8. Fehlerbehebung

SymptomUrsache / Lösung
„Lüftersensor … ist nicht lesbar (Treiber geladen?)“CHIP stimmt nicht mit /sys/class/hwmon/hwmon*/name überein (hier: nct6796, nicht nct6775). Oder das Modul ist nicht geladen: modprobe nct6775.
modprobe nct6796: Module not foundNormal, das Modul heißt nct6775.
Keine Lüfter in sensorsdmesg | grep -i nct prüfen, gegebenenfalls acpi_enforce_resources=lax setzen (Abschnitt 3).
Lüfter zeigt immer 0 RPMFalscher Anschluss in FAN, oder 2-Pin-Lüfter ohne Drehzahlsignal (3- oder 4-Pin-Lüfter nötig).
Keine Mail trotz AlarmOMV-Benachrichtigung prüfen (Testmail in der Weboberfläche), journalctl -u postfix ansehen.
Änderung im Skript wirkt nichtDatei wirklich gespeichert? (vim: :wq) Mit grep '^CHIP' /usr/local/sbin/fan-monitor.sh prüfen.
