01Überblick und Architektur

Auf dem VPS laufen zwei Welten nebeneinander: die öffentliche Seite (Matrix-Clients, Föderation mit anderen Servern, TURN für Anrufe) und das Tailnet (SSH, Synapse-Admin-API, Wartung). Öffentlich erreichbar sind nur die Ports, die Matrix und TURN zwingend brauchen. Alles andere ist ausschließlich über Tailscale erreichbar.

                  Internet
                     |
     +---------------+----------------------------+
     | 80/443 TCP    | 3478, 5349, 49160-49200 UDP | 41641 UDP
     v               v                            v
 +-------+      +--------+                   +-----------+
 | Caddy |      | coturn |                   | Tailscale |
 +---+---+      +--------+                   +-----+-----+
     |  Docker-Netz "matrix"                       | tailscale0
     v                                             v
 +---------+     +------------+              SSH, Admin-API
 | Synapse +-----+ PostgreSQL |              (nur Tailnet)
 +---------+     +------------+

Platzhalter

Alle Werte sind Beispiele. Ersetze sie überall durch deine eigenen:

PlatzhalterBedeutung

Achtung

Der server_name (hier example.org) lässt sich nach der ersten Inbetriebnahme nicht mehr ändern. Vorher bewusst wählen.

02Voraussetzungen

  • VPS mit öffentlicher IPv4 (IPv6 optional), mindestens 2 vCPU, 2–4 GB RAM, 20 GB SSD
  • Debian 12/13 oder Ubuntu 24.04 LTS, Root- bzw. sudo-Zugang
  • Tailscale ist installiert und der VPS im Tailnet angemeldet (tailscale status)
  • Eine Domain, deren DNS du verwalten kannst
  • Eingehende Ports beim Anbieter nicht durch eine externe Firewall blockiert (sonst in der Cloud-Firewall dieselben Ports freigeben wie in Schritt 04)

DNS-Einträge

NameTypWert
matrix.example.orgA / AAAA203.0.113.10
element.example.orgA / AAAA203.0.113.10
turn.example.orgA / AAAA203.0.113.10
example.orgA / AAAA203.0.113.10 (nur, wenn die Domain auch auf dem VPS liegt, siehe 06)
Hinweis

Für turn.example.org darf kein CDN-Proxy aktiv sein (z. B. Cloudflare „orange cloud“). TURN braucht die echte IP, also „DNS only“. Für die anderen Hosts ebenfalls empfohlen.

03Grundsystem und Tailscale Pflicht

System aktualisieren

sudo apt update && sudo apt full-upgrade -y
sudo apt install -y curl ca-certificates gnupg ufw unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades

Tailscale prüfen

tailscale status                 # VPS muss als "online" erscheinen
tailscale ip -4                  # Tailscale-IP merken, z. B. 100.101.102.103
sudo systemctl is-enabled tailscaled

Von deinem Rechner aus testen, dass SSH über das Tailnet funktioniert, bevor die Firewall scharf geschaltet wird:

ssh root@vps          # MagicDNS-Name oder 100.x.y.z

Optional Tailscale SSH aktivieren, dann regeln die Tailscale-ACLs den SSH-Zugriff:

sudo tailscale set --ssh

Was Tailscale auf dem VPS belegt

  • UDP 41641 für direkte WireGuard-Verbindungen (eingehend freigeben, sonst Umweg über DERP)
  • Das Interface tailscale0 mit Adressen aus 100.64.0.0/10 und fd7a:115c:a1e0::/48
  • Ausgehend STUN zu den DERP-Servern von Tailscale, das kollidiert nicht mit coturn
Achtung

Läuft auf demselben VPS zusätzlich ein eigener DERP-Server (derper), belegt der ebenfalls UDP 3478. Dann coturn auf einen anderen Port legen, z. B. listening-port=3479, und die Firewall anpassen.

04Firewall (ufw) Pflicht

Öffentlich freigegeben werden nur Web, TURN und der Tailscale-Port. SSH ist ausschließlich über tailscale0 erreichbar.

sudo ufw default deny incoming
sudo ufw default allow outgoing

sudo ufw allow in on tailscale0          # alles aus dem Tailnet
sudo ufw allow 41641/udp                 # Tailscale direkt

sudo ufw allow 80/tcp                    # Let's Encrypt / HTTP->HTTPS
sudo ufw allow 443/tcp                   # Matrix Client-API + Föderation
sudo ufw allow 443/udp                   # HTTP/3 (optional)

sudo ufw allow 3478                      # TURN/STUN (tcp+udp)
sudo ufw allow 5349                      # TURN über TLS (tcp+udp)
sudo ufw allow 49160:49200/udp           # TURN-Relay-Ports

sudo ufw enable
sudo ufw status verbose
Achtung

Erst aktivieren, wenn ssh root@vps über Tailscale funktioniert. Ein offenes Notfall-Terminal (Webkonsole des Anbieters) bereithalten.

Hinweis

Docker umgeht ufw bei veröffentlichten Ports (ports: in Compose). Deshalb veröffentlicht dieses Setup nur Caddy (80/443) öffentlich. Synapse und PostgreSQL sind öffentlich nicht erreichbar, Synapse ist zusätzlich nur an die Tailscale-IP gebunden (Schritt 06).

Portübersicht

PortProtokollDienstErreichbar
22TCPSSHnur Tailnet
80, 443TCP (443 auch UDP)Caddy: Matrix, Element, Let's Encryptöffentlich
3478UDP + TCPcoturn STUN/TURNöffentlich
5349UDP + TCPcoturn TURN über TLSöffentlich
49160–49200UDPcoturn Relay (Medien)öffentlich
41641UDPTailscale WireGuardöffentlich
8008TCPSynapse direkt (Admin-API)nur Tailnet
5432TCPPostgreSQLnur Docker-intern

Der Relay-Bereich bestimmt die Zahl gleichzeitiger Anrufe (grob 2 Ports pro Teilnehmer). 41 Ports reichen für einen kleinen Server. Für mehr Nutzer den Bereich vergrößern, aber nie über 41641 legen.

05Docker installieren Pflicht

curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
docker compose version

Docker soll erst nach Tailscale starten, weil Synapse an die Tailscale-IP gebunden wird:

sudo mkdir -p /etc/systemd/system/docker.service.d
sudo tee /etc/systemd/system/docker.service.d/after-tailscale.conf <<'EOF'
[Unit]
After=tailscaled.service
Wants=tailscaled.service
EOF
sudo systemctl daemon-reload

06Matrix-Stack mit Docker Compose Pflicht

Verzeichnisse und Geheimnisse

sudo mkdir -p /opt/matrix/{synapse,postgres,caddy/data,caddy/config,element}
cd /opt/matrix

openssl rand -hex 32     # -> POSTGRES_PASSWORD
openssl rand -hex 32     # -> TURN_SECRET (für coturn und Synapse)

Datei /opt/matrix/.env anlegen und auf Rechte 600 setzen:

/opt/matrix/.env
POSTGRES_PASSWORD=<erstes-geheimnis>
TS_IP=100.101.102.103
sudo chmod 600 /opt/matrix/.env

docker-compose.yml

/opt/matrix/docker-compose.yml
services:
  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: synapse
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: synapse
      POSTGRES_INITDB_ARGS: "--encoding=UTF-8 --lc-collate=C --lc-ctype=C"
    volumes:
      - ./postgres:/var/lib/postgresql/data
    networks: [matrix]

  synapse:
    image: matrixdotorg/synapse:latest
    restart: unless-stopped
    depends_on: [postgres]
    volumes:
      - ./synapse:/data
    ports:
      - "${TS_IP}:8008:8008"        # nur über Tailscale erreichbar
    networks: [matrix]

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
      - "443:443/udp"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - ./caddy/data:/data
      - ./caddy/config:/config
    networks: [matrix]

  element:
    image: vectorim/element-web:latest
    restart: unless-stopped
    volumes:
      - ./element/config.json:/app/config.json:ro
    networks: [matrix]

networks:
  matrix:
Hinweis

Für den Produktivbetrieb feste Versionen statt latest eintragen (z. B. matrixdotorg/synapse:v1.xxx.0) und gezielt aktualisieren.

Synapse-Konfiguration erzeugen

cd /opt/matrix
docker run -it --rm -v ./synapse:/data \
  -e SYNAPSE_SERVER_NAME=example.org \
  -e SYNAPSE_REPORT_STATS=no \
  matrixdotorg/synapse:latest generate

Das erzeugt synapse/homeserver.yaml, den Signaturschlüssel und die Log-Konfiguration. Den Signaturschlüssel (*.signing.key) unbedingt sichern.

homeserver.yaml anpassen

Folgende Abschnitte in /opt/matrix/synapse/homeserver.yaml ersetzen bzw. ergänzen:

/opt/matrix/synapse/homeserver.yaml
server_name: "example.org"
public_baseurl: "https://matrix.example.org/"

listeners:
  - port: 8008
    tls: false
    type: http
    x_forwarded: true
    bind_addresses: ['0.0.0.0']
    resources:
      - names: [client, federation]
        compress: false

database:
  name: psycopg2
  args:
    user: synapse
    password: "<POSTGRES_PASSWORD>"
    database: synapse
    host: postgres
    cp_min: 5
    cp_max: 10

# Registrierung: nur durch Admin (siehe Schritt 09)
enable_registration: false

# TURN
turn_uris:
  - "turn:turn.example.org:3478?transport=udp"
  - "turn:turn.example.org:3478?transport=tcp"
  - "turns:turn.example.org:5349?transport=tcp"
turn_shared_secret: "<TURN_SECRET>"
turn_user_lifetime: 86400000
turn_allow_guests: false

# Medien
max_upload_size: 100M
url_preview_enabled: false
Achtung

Das Passwort muss hier im Klartext stehen (Synapse liest die .env nicht). Datei schützen: sudo chmod 640 synapse/homeserver.yaml. Der Container läuft als UID 991, Besitzer ggf. mit sudo chown -R 991:991 synapse setzen.

Caddyfile

/opt/matrix/Caddyfile
# Delegation: Matrix-IDs @user:example.org, Server läuft auf matrix.example.org
example.org {
    header /.well-known/matrix/* Content-Type application/json
    header /.well-known/matrix/* Access-Control-Allow-Origin *
    respond /.well-known/matrix/server `{"m.server":"matrix.example.org:443"}`
    respond /.well-known/matrix/client `{"m.homeserver":{"base_url":"https://matrix.example.org"}}`
}

matrix.example.org {
    reverse_proxy /_matrix/* synapse:8008
    reverse_proxy /_synapse/client/* synapse:8008
    # /_synapse/admin wird bewusst NICHT öffentlich weitergeleitet
}

element.example.org {
    reverse_proxy element:80
}

# Nur damit Caddy ein Zertifikat für coturn holt (Schritt 07)
turn.example.org {
    respond "TURN" 200
}
Hinweis

Liegt die Website von example.org woanders, entfällt der erste Block. Dann müssen die beiden /.well-known/matrix/-Antworten auf dem dortigen Webserver mit demselben JSON ausgeliefert werden.

Durch die Delegation über .well-known läuft die Föderation über Port 443. Port 8448 muss nicht geöffnet werden.

Element Web konfigurieren

/opt/matrix/element/config.json
{
  "default_server_config": {
    "m.homeserver": {
      "base_url": "https://matrix.example.org",
      "server_name": "example.org"
    }
  },
  "disable_custom_urls": false,
  "disable_guests": true,
  "brand": "Element",
  "default_theme": "light"
}

Stack starten

cd /opt/matrix
docker compose up -d
docker compose ps
docker compose logs -f synapse      # auf Fehler achten, Strg+C beendet

Erster Funktionstest:

curl https://matrix.example.org/_matrix/client/versions
curl https://example.org/.well-known/matrix/server
curl http://vps:8008/health          # von einem Gerät im Tailnet -> "OK"

07coturn (TURN-Server) Pflicht

coturn läuft direkt auf dem Host, nicht in Docker. So entfällt das Durchreichen hunderter UDP-Ports, und coturn sieht die echten Client-IPs.

Installation

sudo apt install -y coturn
# Nur ältere Pakete: Dienst in /etc/default/coturn freischalten
sudo sed -i 's/^#TURNSERVER_ENABLED=1/TURNSERVER_ENABLED=1/' /etc/default/coturn 2>/dev/null || true

Konfiguration

Die vorhandene Datei sichern und durch folgenden Inhalt ersetzen:

/etc/turnserver.conf
# --- Netzwerk: nur öffentliche IP, NICHT tailscale0 ---
listening-ip=203.0.113.10
relay-ip=203.0.113.10
external-ip=203.0.113.10
listening-port=3478
tls-listening-port=5349
min-port=49160
max-port=49200

# --- Authentifizierung über das gemeinsame Geheimnis mit Synapse ---
use-auth-secret
static-auth-secret=<TURN_SECRET>
realm=turn.example.org

# --- TLS (Zertifikate siehe unten) ---
cert=/etc/coturn/certs/turn.crt
pkey=/etc/coturn/certs/turn.key
no-tlsv1
no-tlsv1_1

# --- Härtung ---
fingerprint
no-cli
no-multicast-peers
no-software-attribute
user-quota=12
total-quota=1200

# --- KEIN Relaying ins Tailnet oder in private Netze ---
denied-peer-ip=100.64.0.0-100.127.255.255
denied-peer-ip=fd7a:115c:a1e0::-fd7a:115c:a1e0:ffff:ffff:ffff:ffff:ffff
denied-peer-ip=0.0.0.0-0.255.255.255
denied-peer-ip=10.0.0.0-10.255.255.255
denied-peer-ip=127.0.0.0-127.255.255.255
denied-peer-ip=169.254.0.0-169.254.255.255
denied-peer-ip=172.16.0.0-172.31.255.255
denied-peer-ip=192.168.0.0-192.168.255.255
denied-peer-ip=::1
denied-peer-ip=fc00::-fdff:ffff:ffff:ffff:ffff:ffff:ffff:ffff
denied-peer-ip=fe80::-febf:ffff:ffff:ffff:ffff:ffff:ffff:ffff

log-file=syslog
simple-log
Achtung

Die denied-peer-ip-Zeilen sind der wichtigste Teil dieses Setups. Ohne sie könnte jeder Matrix-Nutzer mit TURN-Zugangsdaten den VPS als Sprungbrett ins Tailnet (100.64.0.0/10), ins Docker-Netz (172.16.0.0/12) oder auf lokale Dienste (127.0.0.1, z. B. PostgreSQL oder die Synapse-Admin-API) nutzen.

Hat der VPS auch eine öffentliche IPv6, kann sie zusätzlich angegeben werden (listening-ip/relay-ip je einmal pro Adresse).

TLS-Zertifikat von Caddy übernehmen

Caddy holt bereits ein Zertifikat für turn.example.org (Schritt 06). Ein kleines Skript kopiert es mit passenden Rechten zu coturn:

sudo mkdir -p /etc/coturn/certs
sudo tee /usr/local/bin/coturn-certsync <<'EOF'
#!/bin/sh
set -e
SRC=/opt/matrix/caddy/data/caddy/certificates/acme-v02.api.letsencrypt.org-directory/turn.example.org
DST=/etc/coturn/certs
[ -f "$SRC/turn.example.org.crt" ] || exit 0
if ! cmp -s "$SRC/turn.example.org.crt" "$DST/turn.crt"; then
  install -m 644 -o root -g turnserver "$SRC/turn.example.org.crt" "$DST/turn.crt"
  install -m 640 -o root -g turnserver "$SRC/turn.example.org.key" "$DST/turn.key"
  systemctl restart coturn
fi
EOF
sudo chmod 755 /usr/local/bin/coturn-certsync
sudo /usr/local/bin/coturn-certsync

# täglich prüfen
echo '17 4 * * * root /usr/local/bin/coturn-certsync' | sudo tee /etc/cron.d/coturn-certsync
Hinweis

Der Pfad gilt für Let's Encrypt. Ist Caddy auf ZeroSSL ausgewichen, mit sudo ls /opt/matrix/caddy/data/caddy/certificates/ nachsehen und SRC anpassen.

coturn starten

sudo systemctl enable --now coturn
sudo systemctl status coturn
sudo ss -lunpt | grep turnserver     # lauscht auf 203.0.113.10:3478/5349

In der Ausgabe von ss darf keine 100.x-Adresse auftauchen.

08Admin-Zugriff über Tailscale

Die Synapse-Admin-API ist öffentlich nicht erreichbar, wohl aber über das Tailnet unter http://vps:8008. Von jedem Gerät im Tailnet:

# Access-Token eines Admins (Element: Einstellungen > Hilfe & Info > Erweitert)
TOKEN=syt_...

curl -H "Authorization: Bearer $TOKEN" \
  http://vps:8008/_synapse/admin/v2/users?limit=10

curl -H "Authorization: Bearer $TOKEN" \
  http://vps:8008/_synapse/admin/v1/server_version

Grafische Oberflächen wie synapse-admin lassen sich lokal starten und auf http://vps:8008 zeigen. Wer HTTPS im Tailnet möchte, nutzt tailscale serve:

sudo tailscale serve --bg --https=8448 http://100.101.102.103:8008
Hinweis

Den Zugriff auf den VPS in den Tailscale-ACLs zusätzlich auf Admin-Geräte bzw. -Nutzer einschränken (z. B. nur group:admins auf tag:matrix:22,8008).

09Benutzer anlegen

Ersten Admin anlegen (fragt interaktiv nach Name und Passwort):

cd /opt/matrix
docker compose exec synapse register_new_matrix_user \
  -c /data/homeserver.yaml --admin http://localhost:8008

Weitere Nutzer: derselbe Befehl ohne --admin. Alternativ die Registrierung per Token aktivieren (in homeserver.yaml):

enable_registration: true
registration_requires_token: true

Tokens werden dann über die Admin-API erzeugt:

curl -X POST -H "Authorization: Bearer $TOKEN" -d '{"uses_allowed": 1}' \
  http://vps:8008/_synapse/admin/v1/registration_tokens/new

10Tests

Föderation

  • Im Browser den Matrix Federation Tester (federationtester.matrix.org) aufrufen und example.org prüfen. Alle Prüfungen müssen grün sein.
  • In Element einem öffentlichen Raum beitreten, z. B. #matrix:matrix.org.

TURN

Synapse muss TURN-Zugangsdaten ausgeben:

curl -H "Authorization: Bearer $TOKEN" \
  https://matrix.example.org/_matrix/client/v3/voip/turnServer

Mit diesen Daten (username, password) die WebRTC-Beispielseite „Trickle ICE“ aufrufen, turn:turn.example.org:3478 eintragen und „Gather candidates“ klicken. Es muss ein Kandidat vom Typ relay mit 203.0.113.10 erscheinen.

Gegenprobe der Sperrliste: Ein Relay-Versuch zu einer 100.x-Adresse muss fehlschlagen. Im Log (journalctl -u coturn) erscheint dann „peer IP is denied“ bzw. Fehler 403.

Anruf

Einen 1:1-Videoanruf zwischen zwei Geräten in verschiedenen Netzen starten (z. B. Laptop im WLAN und Handy im Mobilfunk, beide ohne Tailscale).

11Betrieb und Wartung

Updates

cd /opt/matrix
docker compose pull
docker compose up -d
docker image prune -f
sudo apt update && sudo apt upgrade -y      # coturn, Tailscale, System

Vor Synapse-Updates die Release-Notes und Upgrade-Hinweise im Synapse-Repository (element-hq/synapse) lesen.

Backup

Zu sichern sind die Datenbank, das Synapse-Verzeichnis (Signaturschlüssel, Medien) und die Konfiguration:

sudo mkdir -p /root/backup && cd /opt/matrix
docker compose exec -T postgres pg_dump -U synapse -Fc synapse > /root/backup/synapse-$(date +%F).dump
sudo tar czf /root/backup/matrix-files-$(date +%F).tgz \
  .env docker-compose.yml Caddyfile element synapse /etc/turnserver.conf

Backups regelmäßig per Cron erzeugen und außerhalb des VPS ablegen, z. B. per rsync oder restic auf einen Rechner im Tailnet.

Wiederherstellung (Kurzfassung)

# Dateien zurückspielen, dann nur postgres starten:
docker compose up -d postgres
docker compose exec -T postgres pg_restore -U synapse -d synapse --clean < synapse-DATUM.dump
docker compose up -d

13Checkliste

  • DNS-Einträge gesetzt, kein CDN-Proxy für turn.example.org
  • SSH über Tailscale getestet, danach ufw aktiviert
  • Docker startet nach tailscaled
  • homeserver.yaml: server_name, public_baseurl, PostgreSQL, TURN
  • Caddy liefert .well-known und Zertifikate aus
  • Synapse-Port 8008 nur auf der Tailscale-IP
  • coturn lauscht nur auf der öffentlichen IP, denied-peer-ip inkl. 100.64.0.0/10
  • Gleiches TURN-Secret in Synapse und coturn
  • Admin-Nutzer angelegt, Registrierung geschlossen oder per Token
  • Federation Tester grün, relay-Kandidat im ICE-Test, Testanruf erfolgreich
  • Signaturschlüssel und Datenbank-Backup außerhalb des VPS gesichert
