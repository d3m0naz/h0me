WPA-Enterprise mit OPNsense und UniFi

FreeRADIUS läuft auf der OPNsense, die UniFi-APs fragen dort direkt an. Am Ende meldet sich jeder Benutzer mit eigenem Namen und Passwort am WLAN an und landet in einem festen oder per RADIUS zugewiesenen VLAN.

01Überblick

Der Controller ist an der Anmeldung nicht beteiligt. Er verteilt nur die Konfiguration an die APs. Die eigentliche RADIUS-Anfrage schickt jeder AP selbst an die OPNsense.

Client ──WPA2/3-Enterprise──▶ UniFi-AP ──RADIUS, UDP 1812/1813──▶ OPNsense (FreeRADIUS)
                                 │
                                 └─▶ Client landet in VLAN 30
                                     (fest pro SSID oder per RADIUS pro Benutzer)

02Platzhalter

Alle Werte sind Beispiele. Ersetze sie durch deine eigenen.

PlatzhalterBedeutung

03Plugin und Zertifikate Pflicht

  1. Unter System → Firmware → Plugins das Plugin os-freeradius installieren.
  2. Unter System → Trust → Authorities eine eigene CA anlegen, z. B. RADIUS-CA.
  3. Unter System → Trust → Certificates ein Zertifikat vom Typ Server erstellen, signiert von dieser CA, Common Name radius.example.com.
Hinweis

Die CA brauchst du später noch einmal: Sie wird auf die Geräte verteilt, damit sie dem RADIUS-Server vertrauen (Schritt 11).

04EAP einstellen

Unter Services → FreeRADIUS → EAP:

  • Default EAP Type: PEAP mit MSCHAPv2. Das können praktisch alle Clients.
  • CA und Server-Zertifikat aus Schritt 03 auswählen.

05APs als RADIUS-Clients

Unter Services → FreeRADIUS → Clients trägst du die APs ein, nicht den Controller. Am einfachsten gleich das ganze Management-Netz:

FeldWert
IP / Netz10.0.10.0/24
Shared Secretlanges Zufallspasswort, z. B. aus openssl rand -base64 32

06Benutzer anlegen

Unter Services → FreeRADIUS → Users pro Person einen Benutzer mit Passwort anlegen, z. B. alice und bob. Das Feld VLAN bleibt vorerst leer, es wird erst in Schritt 10 interessant.

07Aktivieren und Firewall Pflicht

  1. Unter Services → FreeRADIUS → General den Dienst aktivieren und Log Authentication Requests einschalten. Ohne dieses Log ist die Fehlersuche Raten.
  2. Auf dem Interface, über das die APs kommen, eine Regel anlegen:
QuelleZielProtokoll / Port
10.0.10.0/2410.0.10.1UDP 1812 (Auth), 1813 (Accounting)

08RADIUS-Profil in UniFi

Unter Settings → Profiles → RADIUS → Create New:

  • Authentication Server: 10.0.10.1, Port 1812, Shared Secret aus Schritt 05
  • Accounting: optional, 10.0.10.1, Port 1813

09SSID anlegen

Unter Settings → WiFi eine neue SSID Beispiel-WLAN anlegen oder eine bestehende umstellen:

  • Security: WPA2-Enterprise, oder WPA2/WPA3-Enterprise, wenn alle Geräte WPA3 können
  • RADIUS-Profil: das Profil aus Schritt 08
  • Network: das Netz mit VLAN 30

Damit läuft die einfache Variante: Wer sich an Beispiel-WLAN anmeldet, muss sich per RADIUS ausweisen und landet in VLAN 30.

10VLAN pro Benutzer Optional

Mit einer einzigen SSID kann jeder Benutzer in einem eigenen VLAN landen, z. B. alice in 30 und bob in 40.

  1. UniFi: im RADIUS-Profil Enable RADIUS assigned VLAN for wireless network einschalten.
  2. OPNsense: beim Benutzer das Feld VLAN ausfüllen. FreeRADIUS schickt die ID dann als Tunnel-Private-Group-ID an den AP.
Voraussetzung

Jedes VLAN, das RADIUS vergeben kann, muss in UniFi als Netzwerk existieren und auf den Switch-Ports der APs getaggt sein. Sonst hängt der Client ohne Adresse in der Luft.

11Geräte und Zertifikate

  • Android ab 11 will im WLAN-Profil eine CA und eine Domain. Die CA aus Schritt 03 exportieren, auf dem Gerät installieren und als Domain radius.example.com eintragen. Mit einem öffentlich signierten Zertifikat reicht stattdessen „Systemzertifikate“ plus Domain.
  • Windows und macOS fragen beim ersten Verbinden nach, ob sie dem Zertifikat trauen sollen. Einmal bestätigen, fertig.
  • Bei vielen Geräten die CA lieber per Profil verteilen, unter macOS und iOS z. B. als .mobileconfig.

12Fehlersuche

Erster Blick immer in Services → FreeRADIUS → Log File:

Im LogWahrscheinliche Ursache
gar nichtsNetz, Firewall-Regel (falsches Interface?) oder der AP fehlt unter Clients
RejectBenutzer, Passwort oder Zertifikat
Klassiker

Die Anfrage kommt von der IP des APs, nicht vom Controller. Steht unter Clients nur die Controller-IP, wird jede Anfrage stillschweigend verworfen.

13Ausbaustufen

  • Kabel: Derselbe RADIUS kann Ports an UniFi-Switches per 802.1X absichern.
  • IoT: Geräte ohne Enterprise-WLAN lassen sich per MAC-Authentifizierung (MAB) anbinden. Das ist bequemer, aber MAC-Adressen sind leicht zu fälschen.
